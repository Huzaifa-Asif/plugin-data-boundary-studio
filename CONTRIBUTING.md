# Contributing

Open an issue before a large change. Keep the project dependency-free unless a dependency has a documented need and security review. Never use real credentials or personal records in issues, examples, tests, or screenshots.

Before a pull request:

```sh
npm run check
```

Include tests for direct, indirect, negative, follow-up, and boundary behavior when applicable. Keep automated findings narrow and explain any new rule in the README and threat model. By contributing, you agree that your contribution is licensed under MIT.
